# the-boxes · 界面风格规则（Style Guide）

> 版本 v0.3.10 · 2026-09-19 · **本文是界面视觉的唯一事实源。**
> `src/styles.css` 必须服从本文；两者不一致时，以本文为准，并视为待修复缺陷。
> 视觉改动流程：先改本文 → 再改 `styles.css` → 在文末变更日志追加一条。

## 1. 设计理念

1. **内容是唯一的主角**：不装饰元素。用留白、缩进与字重表达层级，而不是用边框、阴影、底色。
   每新增一个视觉元素，先回答"它承载了什么信息"；答不出就不加。
2. **两个信号胜过三个弱信号**：当某个元素"浮不起来"时，正确做法是**去掉它**或加强唯一手段，而不是叠加边框＋阴影＋底色去补偿。
3. **单一色相派生**：全部中性色由一个 HSL 基准派生。改基准即改整套配色。
4. **语义色只做强化，符号才是主通道**：颜色不得是唯一的信息载体（色觉障碍、灰度屏、打印均需可读）。
5. **易读性优先于美观**：任何对比度不达标的"高级感"都是缺陷，见 §2.3。
6. **为反馈而动，不为表演而动**：动效上限 150ms（§2.4）。
7. **日日用的"轻"**：一屏看得下更多，比看得更精致重要。

## 2. 设计 Token

### 2.1 中性色（由基准派生，唯一基准）

```css
--base-h: 38;      /* 暖纸色相：比纯灰柔和，降低长时间注视的冷硬感 */
--base-s: 12%;
--base-l: 97%;     /* 页面底色 = 基准本身 */
```

所有中性色 = `hsl(var(--base-h) var(--base-s) <基准亮度 − 偏移>)`。

| Token | 偏移 | 实际值 | 用途 |
|---|---|---|---|
| `--bg-page` | 基准 | `#f8f8f6` | 页面背景 |
| `--bg-surface` | 固定白 | `#ffffff` | 浮层、输入框、浮起表面 |
| `--bg-hover` | l−4 | `#efeeeb` | 行悬停底色 |
| `--bg-sunken` | l−6 | `#ebe9e5` | 内嵌代码、弱底衬、「今日」标记底 |
| `--divider` | l−12 | `#dddad4` | 分隔线（**非组件边界**，不受 §2.3 约束） |
| `--border-control` | l−43 | `#988d7c` | 交互控件描边（**须 ≥3:1**） |
| `--text-secondary` | l−58 | `#6f6758` | 次级文本、元数据、完成项文字、box 描边与符号 |
| `--text` | l−88 | `#1a1814` | 正文、标题 |

**深色 token 必须对四种表面同时达标，取最严者。** 本项目最暗的表面是 `--bg-sunken`，它决定下限：

| Token | `--bg-page` | `--bg-hover` | `--bg-sunken` | `--bg-surface` | 判定 |
|---|---|---|---|---|---|
| `--text` | 16.67:1 | 15.28:1 | 14.62:1 | 17.73:1 | ✅ |
| `--text-secondary` `#6f6758` | 5.26:1 | 4.82:1 | 4.61:1 | 5.59:1 | ✅ |
| ~~`#786f5e`（v0.3 初稿）~~ | 4.66:1 | 4.27:1 | 4.09:1 | 4.96:1 | ❌ 悬停即跌破 4.5:1 |
| `--border-control` `#988d7c` | 3.07:1 | 2.81:1 | 2.69:1 | 3.26:1 | ⚠️ 仅可在 page / surface 上 |

- `--border-control` 只对 page 与 surface 达标，因此**交互控件不得放在 `--bg-hover` / `--bg-sunken` 表面上**。
- **只有两个文本层级。** 比 `l−58` 更浅的灰字在 `--bg-sunken` 上无法达到 4.5:1，因此不存在"第三级更淡的灰字"——需要更弱时，用**字号**（11px）和**字重**（400）降级，不要用更浅的颜色。

### 2.2 语义色（仅两个，固定值，不参与派生）

| Token | 值 | 唯一含义 | 阈值 |
|---|---|---|---|
| `--c-done` | `#4f7a33` | **表达"完成"**（状态框填充） | 作图形 ≥3:1：page 4.74 / sunken 4.16 ✅ |
| `--on-done` | `#ffffff` | 完成勾的前景（在 `--c-done` 实心上） | 5.04:1 ✅ |
| `--accent` | `#0e7490` | **应用主色**：品牌标记 + 焦点环 + 主操作 | 作图形 ≥3:1：5.04:1 ✅ |
| `--accent-focus` | `hsla(193 82% 31% / 0.16)` | 焦点环专用 | 即 `--accent` 本身 16% alpha |

规则：**语义色的含义必须唯一，且不得跨义复用。**

- `--c-done` 的语义是"完成"。凡**表达完成**的场景都可用（如状态框填充）——此时颜色与含义一致，是强化而非复用。
- 用 `--c-done` 表达**其他含义**则禁止。典型反例：「今日」标记若用绿色，会让"绿 = 完成"的约定失效。
- `--accent` 是应用主色，**不表示任何状态**：不得用青绿表示"进行中""已完成"或任何五状态之一。
- 其余全部状态差异由符号承担（§4.2），不新增状态色。
- `--accent-focus` 必须由 `--accent` 派生（注意 `#0e7490` 实为 `hsl(193 82% 31%)`，不要照抄近似值）。

### 2.3 对比度硬约束（可机械验证）

阈值取 WCAG 2.1 AA。**比较基准是"该元素实际会落在的每一种表面"中最不利的那一种**，而不是只算页面底色：

| 对象 | 阈值 | 说明 |
|---|---|---|
| 正文与元数据文本（任意字号） | **≥ 4.5:1** | 本项目最小字号 11px，不享受"大字号 3:1"豁免 |
| 交互控件边界（下拉、输入框、日期框） | **≥ 3:1** | WCAG 1.4.11 非文本对比度 |
| 状态符号与图标（含状态框填充） | **≥ 3:1** | 同上 |
| 纯分组用分隔线、悬停底色 | 无要求 | 不承载信息，不可作为唯一区分手段 |

务必注意：**悬停底色本身会降低对比度**（`--bg-hover` 比 `--bg-page` 暗，`--bg-sunken` 更暗）。因此"在页面上看起来够黑"不等于合格——必须把 `--bg-hover` / `--bg-sunken` 一并代入。v0.3 初稿的 `--text-secondary`（`#786f5e`）正是在这一步被查出：页面上 4.66:1 合格，**鼠标一悬停行就跌到 4.27:1**。

新增或修改任何颜色后，必须重新核算其**全部可能表面**的对比度并在变更日志记录实测值。

### 2.4 圆角、阴影、动效

```css
--radius-row: 8px;       /* 行（仅用于悬停底色，行本身无边框） */
--radius-control: 8px;   /* 下拉、输入框、菜单项 */
--radius-pop: 12px;      /* 浮层 */
--radius-pill: 999px;    /* 胶囊（如使用） */

--shadow-pop: 0 8px 24px -10px rgba(31, 28, 23, 0.18);  /* 仅浮层 */

--dur-fast: 120ms;       /* 悬停、颜色、透明度 */
--dur-base: 150ms;       /* 上限，不得超出 */
--ease: cubic-bezier(0.22, 0.61, 0.36, 1);
```

- **阴影只有一个，且只用于浮层。** 列表行、卡片、容器一律无阴影。
- 动效只允许 `color / background-color / opacity / transform: scale()`。
  **禁止位移**（`translateY`、`translateX`）、拉长、旋转、扫光。
- 禁止逐行错峰入场（stagger）。列表淡入若保留，整体一次性 ≤120ms。

### 2.5 字体栈

```css
--font-stack: -apple-system, BlinkMacSystemFont, 'Segoe UI', Inter, Ubuntu,
  'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif;
```

- system-first，不打包字体文件（原生感与性能，沿用 Minimal 方法）。
- `-webkit-font-smoothing: antialiased` 常开。
- 数字不强求等宽；但计数等会跳动的数字用 `font-variant-numeric: tabular-nums`。

## 3. 字号与层级

四个层级，对应四种角色（不绑定具体元素，允许元素换位）：

| Token | 字号 | 字重 | 角色 |
|---|---|---|---|
| `--fs-title` | 17px | 600 | 页面标题 |
| `--fs-body` | 15px | 400 | todo 正文 |
| `--fs-label` | 12px | 500 | 菜单项、按钮、次级标签 |
| `--fs-meta` | 11px | 400 | 元数据、日期、注记 |

- 正文下限 14px，元数据下限 11px，**低于 11px 禁止**。
- 行高：正文 1.5；元数据 1.4。
- 字重只用 400 / 500 / 600 三档，且只用于上表规定的位置。
- 中文加粗在 mac 上易糊，`600` 仅用于标题；不要用 700。

## 4. 间距与尺寸

基准网格 **4px**。下表为规定用法，不得自行取整到 5/6/7 等非 4 倍数。

| 用途 | 值 |
|---|---|
| 页面最大宽 | 864px，居中（v0.3.8 起：侧栏 200px + 间距 28px + todo 列 ≈ 636px） |
| 页面上下内边距 | 48px 上 / 56px 下 |
| 页面左右内边距 | 20px（窄屏 16px） |
| 标题区与列表间距 | 20px |
| 侧栏宽度 | 200px（mini 日历 + 任务卡片），与 todo 列间距 28px，页面滚动时吸顶（`top: 24px`） |
| 日历格间距 | 2px（格子 aspect-ratio 1:1） |
| 任务卡片内边距 | 8px，卡片间距 2px |
| 行内边距 | 10px 上下 / 12px 左右 |
| 行最小高度 | 40px（保证点击区域） |
| 行间距 | 0（用分隔线，不用间隙堆叠） |
| 行内元素间距 | 12px |
| 分组之间 | 24px 以上，用留白而非分割线 |

### 4.1 行模型（本项目的核心规则）

**行不是卡片。** 每一行必须是：

- **无边框、无背景、无阴影**；整行可点，悬停时整行铺 `--bg-hover`，圆角 `--radius-row`。
- 与下一行之间用 **0.5px `--divider` 分隔线**，且**从文字起点缩进**（左侧留出状态框宽度）——这是"缩进分隔线"而非通栏横线，视觉上把状态框和内容分成两栏。
- 分隔线在悬停行及其**相邻行**上隐藏，避免与悬停底色打架。

```css
.todo { position: relative; padding: 10px 12px; min-height: 40px;
        border: none; background: none; box-shadow: none; }
.todo:hover { background: var(--bg-hover); }
.todo + .todo::before {           /* 缩进分隔线：left 对齐文字起点 = 12 + 18 + 12 */
  content: ''; position: absolute; left: 42px; right: 0; top: 0;
  height: 1px; background: var(--divider);
}
.todo:hover::before,
.todo:hover + .todo::before { opacity: 0; }
```

这条规则为什么重要：`--divider` 对页面底只有 1.31:1、`--bg-hover` 只有 1.09:1，两者都是弱信号。**不允许再叠加边框和阴影去"加强"它**——弱信号本就不该被加强，它只需要不干扰阅读。（v0.2 曾因叠加而退化为"卡片墙"，见变更日志。）

### 4.2 状态框

| 项 | 值 |
|---|---|
| 尺寸 | 18px × 18px（定值，不用 `calc`） |
| 形状 | 圆形（`border-radius: 50%`） |
| 描边 | 1.5px `--text-secondary` |
| 符号字号 | 12px / 500 |

| 状态 | 符号 | 填充 | 描边/符号色 |
|---|---|---|---|
| `[ ]` 待办 | 无 | 透明 | `--text-secondary` |
| `[/]` 进行中 | 半填充圆（45° `/` 分割） | `currentColor` 的左上半 | `--text-secondary` |
| `[x]` 完成 | 矢量勾（`✓` 形态） | `--c-done` 实心 | `--c-done` |

- 符号尽量沿用文件语法的字符，便于用户把界面与 Markdown 原文对应起来。**`[x]` 与 `[/]` 是既定例外**：它们要表达的形态字形给不了（`x` 不是勾、斜杠 `/` 不表达"进行中"），故用矢量绘制。（v1.x 的 `[>]` `[<]` 字形已随 SPEC v2.0 删除）
- **三个状态只有"完成"有颜色。** 两个未完结状态共用 `--text-secondary`，靠符号区分——这既是 §1.4 的要求，也让未完成的任务不会互相抢注意力。进行中的半填充因此也用 `currentColor`（= 外圈那个灰），**不引入新色值**。
- 符号不可省略：颜色不是唯一载体。
- **禁止用渐变做半填充**（v0.2 的 `--c-doing-tint` 已删除），也禁止用渐变做任何"进度填充"。半填充必须是**真实的矢量形状**（半个圆盘），而不是一层色带。

**进行中的半填充圆（机械可验证）**

| 项 | 值 | 来源 |
|---|---|---|
| 分割线方向 | 45°（`/`），过圆心 | 与文件语法里的 `[/]` 同向 |
| 填满的那半 | 左上（`/` 左上侧） | 与列表阅读方向一致（左→右、上→下）；等同 Unicode ◐「左半实心」顺时针转 45° |
| 分割线两端（屏幕角） | 135.00° / 315.00° | 实测 134.87–134.94° / 314.91–314.93°，各半径偏差 ≤ 0.13° |
| 填充角度跨度 | **180.00°** | 315 − 135，即正好一半 |
| 填充半径 | 9px（= 框外缘半径），再由 `.box` 的圆角裁到描边内缘 | 见下两条 |
| 空隙 | **无** | 实测沿填充半区各角度、半径 0.2→9px，α_min ≥ 0.58 |

- **为什么按整框直径画、靠裁剪收边**：若改用 `calc(18px − 2 × 描边)` 去算内区尺寸，会撞上**描边宽度被设备像素吸附**这件事——DPR 1 时 1.5px 被 Chrome 吸附成 1px，框内区由 15px 变成 16px，按 15px 算出来的半圆就比内缘小 0.5px，弧上露出一条细缝。让填充画满 9px 半径、由 `.box` 的 `border-radius` 裁到内缘之后，"贴合"成了裁剪的副产品，**与描边究竟多宽无关**，任何 DPR 都严丝合缝。
- 由此两条硬约束：`.box` 必须保留 `overflow: hidden`（去掉它，填充会盖住外圈）；`.box-half` 必须与框的**边框盒**重合（实测 △left/△top/△right/△bottom 全为 0——flex 把超出的 18px 居中，左右各溢 1.5px）。
- **只填不描**：外圈已提供 1.5px 圆环。若再给这段弧描一笔（0.9px），这个状态的环会变成约 1.95px、比其他四态粗一圈。分割线也不必另画——它就是半圆盘的直边，与外圈同色，画了也看不出来。
- 几何不写进像素：viewBox 取**单位圆**（2×2，圆心 (1,1)，半径 1），尺寸只由 CSS 给（`width/height: var(--checkbox-size)`）。半径 1 永远等于"框外缘"，不随 `--checkbox-size` 改值而失准。

**符号笔画宽度（机械可验证）**

| 项 | 值 | 来源 |
|---|---|---|
| `/` 笔画宽 | 0.78px | 实测（12px/500 字形轮廓） |
| `>` `<` 单臂笔画宽 | 0.94px | 实测（同上，取单臂垂直剖面） |
| 完成勾 `stroke-width` | **0.9px** | 落在 0.78–0.94 带内，与两个折线符号最接近 |
| 完成勾居中偏差 | **0.00px** | 墨迹包围盒中心 = viewBox 中心 (6,6) |
| 半填充圆分割线 | 不描边 | 直边即填充边界，与填充同色（见上） |

- 量法：把 `src/styles.css` 内联到只含状态框的探针页，`--force-device-scale-factor=16` 截图，从实底/实字色反解**覆盖率场 α**（不是二值阈值），取 α≥0.5 为几何真边，再用**垂直剖面**量 0.5 交叉点间距。
- **不要用最大内切圆（EDT）量折线符号的线宽**：折角处的最大内切圆会横跨两条臂，实测把 1.30px 的勾读成 1.56px。EDT 只对无拐角的直棒（如 `/`）可用。
- 完成勾必须用矢量绘制，不得用 CSS 边框拼 L 形（`border-left` + `border-bottom` + `rotate(-45deg)`）：
  - 线宽会等于边框宽度，而 1px 边框的实际墨迹是 2 条各 1px 的边，勾因此变成 2px，比所有字形都粗一倍；
  - L 形绕自身中心旋转 45° 后，**墨迹包围盒中心与旋转原点不重合**（v0.3 实测偏左 1.4px、偏下 0.7px），只能靠 `translate` 补一个随尺寸漂移的魔数。
  - 矢量折线（`<polyline>`，`stroke-linecap/linejoin: round`）的墨迹包围盒天然以 viewBox 中心为心，flex 居中即勾居中，且线宽是独立参数、不随容器尺寸变化。

## 5. 组件规则

### 5.1 元数据（任务、日期、注记）

- **一律 11px / 400 / `--text-secondary`，右对齐，最多 2 项，超出省略。**
- **不使用彩色底 + 深色字的胶囊。** v0.2 的 `--chip-task-*` / `--chip-date-*` 四个色值已删除；两个色相只为区分"任务"和"日期"而存在，性价比为负。
- **元数据保留文件里的标记与完整值**：日期显示为 `@2026-09-22`（完整 ISO——它同时是当日的文件名），任务显示为 `@装修`。目的是让界面上的每一项都能指回它的来源：`@YYYY-MM-DD` → `inbox/YYYY-MM-DD.md`，`@装修` → `tasks/YYYY-MM/装修.md`（v0.3.10 起任务按提出月份嵌套，月份由任务卡片与平铺组头显示）。
  - **任务项的记号与文件不一致，这是刻意的，且目前只统一在显示层**：SPEC §4 的文件语法是 `+任务slug`，界面显示 `@装修`。解析器读文件时**仍只认 `+任务slug`**——手写 `@装修` 不会生效，会原样留在标题文本里。界面写文件时也不改写任务 token，所以不会破坏已有数据。若要文件侧也认 `@`，需扩展解析器 + 改 SPEC §4，属独立决定。
  - 界面**不再**去掉前缀（v0.3.3 曾把 `+装修` 显示成 `装修`、`@2026-09-22` 显示成 `9/22`，已按用户决定撤销）。
- 日期短格式：同年 `M/D`；非同年 `YYYY/M/D`。**只适用于日期下拉框的选项**（`value` 保持 ISO）。元数据 chips 一律完整 ISO——因为它同时是文件名。
- **不使用 emoji 作为界面元素**（跨平台字形不一致，且违反 §1.1 克制原则）。
  用户在 todo 文本里自己写的 emoji 原样显示，不属于界面元素。
- 不使用破折号、括号等连接词拼装注记；多项元数据靠间距和对齐区分。
- **起止日期注记是上述两条的既定例外**（唯一一处）：

  | 数据 | 显示 |
  |---|---|
  | 有开始日（可含完成日） | `——始于 YYYY-MM-DD 🛫`，有完成日时续 `，完成于 YYYY-MM-DD 🎉` |
  | 只有完成日 | `——完成于 YYYY-MM-DD 🎉` |

  例外成立的理由：注记是**面向文件**的行内说明，不是界面控件。它用文件的 ISO 日期（与 inbox 原文一一对应）、并保留用户自己的 `——` / `🛫` / `🎉` 记号，因此不适用"界面不用 emoji""日期短格式"两条。
  同日不特殊处理——注记是原样陈述起止，不做"折叠"这类加工（v0.3.3 一度改成 `9/18 → 9/19` 并按同日折叠，已按用户要求撤销）。

### 5.2 焦点态

- 可聚焦元素统一 `outline: none` + `box-shadow: 0 0 0 3px var(--accent-focus)`。
- **不得移除焦点样式**而不提供替代。键盘操作是核心路径（PLAN 北极星指标含"状态切换 ≤2 秒"）。

### 5.3 mini 日历 + 任务卡片（v0.3.8 起）

左上 mini 日历、其下任务卡片列表，右侧 todo 列表。日历的日期格与任务卡片都是导航；日期格同时是拖放目标。

**mini 日历**

- 月历：**周一开头**，周标题「一 二 三 四 五 六 日」（11px / `--text-secondary`）；网格 7 列，格间距 2px，格子 `aspect-ratio: 1`；日期数字 11px / `tabular-nums`，居中。
- 头部：月份标题「N月 YYYY」（12px / 600），**点它回本月**；‹ › 翻月按钮 24px 方形，悬停 `--bg-hover`。
- 有记录的日期：数字下方 3px 圆点，`--text-secondary`。存在性提示用中性色——绿色已被"完成"占用，不跨义复用（§2.2）。
- 今天：`inset 0 0 0 1.5px var(--border-control)` 描圈 + 字重 600。描圈而非底色：今天不是选中态，只是参照点；`--bg-sunken` 底色留给选中。
- 选中（正在查看的那天）：`--bg-sunken` 底 + 字重 600。
- 拖放高亮（todo 拖到某天上时）：`--accent-focus` 背景 + `inset 0 0 0 1.5px var(--accent)` 描边。描边用 inset 不占布局；`--accent` 是"可交互目标"语义（与焦点环同源），不引入新色值。
- 日期格**不显示文件是否存在**——未来日期是合法点击与拖放目标，文件在 drop 时才创建。
- 焦点环同 §5.2。

**任务卡片**

- 列表标题「任务」：11px / 500 / `--text-secondary`，内边距 `0 8px`。

**任务详情头（任务视图渲染，位于主区标题 §5.4 之下）**

**窄屏（≤720px）**

### 5.4 主区标题「接下来干啥？」（v0.3.9 起）

主区顶部的常驻标题，所有视图都渲染；**点击回到平铺视图**（已在平铺时点击无变化）。平铺是默认视图（SPEC §2），这个标题既是它的名字，也是从筛选返回的入口。

- 文字固定为「接下来干啥？」；17px / 600（`--fs-title`）、`letter-spacing: -0.02em`（与品牌 h1 一致）、`--text`。
- 它是按钮，不是静态标题：零衬底零描边，悬停 `--bg-hover`，圆角 `--radius-control`，焦点环同 §5.2。平铺态（`aria-current="true"`）无特殊样式——标题本身就是当前态的陈述，不需要再标一次。
- 内边距 4px 8px、左外边距 −8px：负 margin 抵消按钮自身的左 padding，让**文字左缘**与下方 todo 行悬停底色的左缘（main 左缘）对齐。padding 保留是为了悬停底色不贴死文字。
- 与下方内容间距 16px；任务视图时详情头（§5.3）紧随其后，两段间距相等。
- **平铺视图按来源分组**（v0.3.10 起，取代 v0.3.9 的行尾来源 chip）：todo 按来源文件归组，**组头直接显示来源文件名称**——inbox 组为日期（即文件名，如 `2026-09-19`），任务组为任务名 + 较淡的提出月份（如 `装修 2026-09`，月份区分跨月重名）。组头 11px / 500 / `--text-secondary`（月份字重 400，左间距 6px），与下方列表间距 4px；组间留白 24px（§4），首组无上间距。行尾不再标注来源；todo 自身的元数据（`@日期`、`+任务`）不受影响，照常按 §5.1 显示。筛选视图（某日 / 任务）单一来源，无组头：筛选动作本身已指明来源文件，再标一次是冗余。

## 6. 禁止项

- 页面或容器背景使用渐变、纹理、噪点、模糊、磨砂。
- 行、卡片、容器使用 `box-shadow`（唯一例外：浮层）。
- 悬停时元素发生位移（`translate`）。
- 硬编码色值出现在组件规则中（`#hex`、`hsla()` 字面量）——**必须走 §2 的 token**。
- 动效时长 > 150ms，或逐行错峰入场。
- 语义色它用（§2.2）。
- 字号 < 11px。
- 界面文案暴露实现细节（文件路径、环境变量名、版本号、内部状态枚举名）。
  - **例外一：footer。** footer 显示「数据目录 · 软件版本 · 数据格式版本」，不带 `数据` / `数据格式` 这类标签前缀。用户需要知道数据落在磁盘哪里、自己跑的是哪一版——这属于产品主张（数据在自己手里），不是实现泄漏。
  - **例外二：空态的来源文件。** 空态必须写出 todo 的来源文件全名（`…/inbox/2026-09-19.md`）——"去文件里加一行"是本产品的基本用法，文件名本身就是操作指引，省略掉用户就无从下手。
  - **两处例外都必须用接口给的值，不得硬编码。** 取 `GET /api/info`（开发期由 `vite.config.ts` 现读 `package.json` 与 `SPEC.md`）。v0.3.2 的 footer 把 `SPEC v1.0` 写死在界面里，SPEC 升到 v1.2 后界面就开始说谎；空态写死默认路径 `~/the-boxes`，配过 `.env` 的用户会看到一条指向不存在文件的指引。**值的单一来源**是这条规则的实质，不是措辞问题。
  - footer 与空态之外的任何位置不得出现路径、环境变量名、版本号。
  - 状态名对外一律用中文（待办 / 进行中 / 完成）。`done` / `scheduled` 这类内部枚举名不得出现在可见文案，也不得出现在 `aria-label`。
